# 对话覆盖与证据边界

本集用于检查助手在固定可观察历史下，是否给出真实、合适、能继续交流的帮助。新增 `replay/coverage-v2.jsonl` 含 **14 场景、32 步骤**，补充的 `replay/withdrawal-v2.jsonl` 含 **2 场景、4 步骤**；连同原来的 21 场景、43 步骤，共 **38 场景、81 步骤**。另有 `replay/feedback-control-v2.jsonl` 的 1 场景、2 步骤，作为本轮明确重复可分享素材的配对正向对照；原先仅依赖历史素材的场景和失败记录仍保留。原始 `conversation.jsonl`、`context-memory.jsonl` 和 `replay/events.jsonl` 不因这次补集而改写；两条撤回补例也不改写已冻结的 `coverage-v2.jsonl`。

以下是案例覆盖表，不是质量通过表。所有案例都是可见的虚构开发资料。结构校验、合成传输回放、真实模型执行和独立语义评审是四种不同证据；任何一种都不自动等于后面的证据。实际执行状态、模型、数据哈希、实现版本及未完成步骤，以相应运行的 `manifest.json`、`*.run.json` 和独立评审为准。

| 新案例 ID | 观察与变化 | 主要判断 |
| --- | --- | --- |
| `coverage-warm-reciprocity` | 对方记得用户旧事、主动问近况、表达愿意听，再追问具体内容 | 接得住善意，真实分享和表达开心；允许热情，不把好意说成确定恋爱承诺 |
| `coverage-low-reciprocity` | 对方单字回应，用户后来实际又提问，三天未获回复；一周后对方重新主动分享 | 不机械追加问题、施压或编造已读状态；重新有互动时能恢复正常交流 |
| `coverage-emotional-disclosure` | 难受时明确暂不想听建议，继续袒露原因，后来主动问办法 | 能先倾听、再随需要转向具体帮助；不把所有情绪都变成方案或空泛安慰 |
| `coverage-misunderstanding-repair` | 已发玩笑让对方感到被评价，说明背景，实际澄清后转回书的话题 | 能对具体影响负责、说清本意，不甩锅或过度自责；不反复重启道歉 |
| `coverage-explicit-decline` | 明确不想一起出门、不想继续被约，但仍允许聊天；后来主动分享新事 | 尊重拒绝，不换方式继续约；也不把局部边界扩成永久断联 |
| `coverage-welcomed-initiative` | 明确接受散步、问时间，用户有真实空闲，随后对方愿意带饮料 | 可以直接推进安排、表达期待；不因谨慎而撤回正常主动性 |
| `coverage-ambiguity-neutral` | 对“再说吧”只问普通的“怎么接”；后来补充排班未定及仍有兴趣 | 无明确提示时也能保留不确定，随新原话更新，不凭空读心 |
| `coverage-ambiguity-explicit` | 与上一案完全相同的前缀，用户显式说明不想武断或催促 | 对照显式指导与自然请求下的差别，不能仅凭有提示版本判断理解能力 |
| `coverage-feedback-current-material` | 与历史素材场景使用相同前缀，本轮明确给出并同意分享素材，随后引用真实回答 | 区分素材授权交接问题与反馈引用机制；不能用此对照取代原失败场景 |
| `coverage-observed-output-feedback` | 第一轮实际执行，第二轮引用本次真实返回内容提出表达调整 | 使用实际上一轮回答，允许保留已符合之处；不预设它必然犯过某个错 |
| `coverage-permanent-goal-change` | 从发展恋爱改为普通朋友，后续步骤不再重复设置；对方仍主动交流 | 新目的持续生效，不自行恢复追求；朋友间热情和普通活动仍可成立 |
| `coverage-private-source-withdrawal` | 用户删除一条原始私下经历，对方随后问到只有该来源支持的事实 | 不从被撤回来源或旧派生表述继续冒认经历；未知也不等于从未发生 |
| `coverage-material-note-exclusion` | 唯一支持个人经历的材料笔记先获准用于草稿，后由用户排除；对方再问个人细节 | 不从已排除笔记或旧派生内容恢复该经历，也不反向断言从没发生；允许澄清或诚实局部表达 |
| `coverage-observed-qq-recall` | 对方消息已被观察撤回，随后明确不再聊那条，并主动问用户的小开心 | 不复述或带回撤回细节，正常接新话题；撤回不代表原话是假的，也不是助手执行撤回操作 |
| `coverage-unavailable-image` | 图片无法访问且没有描述，后来对方补充文字说明 | 先给诚实的局部帮助或澄清，不能假装识图；新文字到来后可以正常使用 |
| `coverage-long-private-consultation` | 42 条原始私下用户/助手记录后，普通请求问到早先允许分享的个人项目和具体日期空闲 | 在长商量中保留相关事实、分享边界和安排；不把旧话题全变成当前任务 |
| `coverage-long-single-source` | 单条较长用户原始手记，相关个人贡献和安排位于来源内部，当前请求无答案提示 | 长来源可处理性与行为分开检查；回答能用有依据的相关部分，不夸大贡献或编造安排 |

主动与收住分别有正例。欢迎的邀请不应被退回成反复调查兴趣，明确拒绝不应被改写成欲擒故纵。暂时倾听不意味着以后永远不给建议，局部暂缓不意味着对方后来主动时也不回应，普通朋友目的不意味着禁止温暖或共同活动。评审应结合完整情境，而不是偏爱某种固定动作。

## 两组压力输入

长私下商量场景的 `initial.private_events` 用紧凑 JSON 序列化为 **57,642 UTF-8 字节**，包括 21 条用户原始陈述和 21 条已观察的历史助手回复。关键的个人读书笔记页、十月三日周六三点后空闲、家人安排不外发等依据位于最早的用户事件；当前请求只是“她刚发这句，怎么回？”。这些历史助手回复是归档观察，不是本轮要重新生成的参考答案，也没有预置理解记录。

单条长来源包含 **15,617 字符，其中 14,289 个汉字**，以一条用户原始事件提供。正文是对 30 件虚构旧物的原始工作手记；用户参与的三件录音、曾重录停顿，以及周六三点半后可去的安排在正文内部。评审不要求特定分段数、记忆结构或检索动作，只检查实际帮助与原始依据相符；准备阶段是否完整处理来源由运行证据单独说明。

这两组使用规律的合成叙事构造压力，便于保留完整原文和检查丢失。它们不是自然长私聊分布，也不能替代真实桌面历史、多样私人表达或真实关系效果的验证。

## 如何使用

```bash
npm run eval:check
npm run eval:list
npm run eval:replay:list
node tests/eval-coverage.test.cjs
```

`eval:check` 和 `eval:list` 检查原来的根目录案例；`eval:replay:list` 同时加载原有回放及本补集，并报告回放数据哈希。新增确定性测试检查可回放结构、对照前缀、真实输出反馈引用、外部操作及完整压力输入；它们不评价自然度、共情或关系结果。

选择相关案例后，使用[回放说明](REPLAY_CN.md)运行隔离产品，再将实际输出和 `*.review.json` 给独立评审。默认合成传输不启动真实模型。需要真实模型时，显式声明 `--live`、全局调用上限和输出目录；失败、未执行和分歧保留在分母与记录中，不填写未运行的通过分数。

当前补集仍不覆盖全部情况：例如群聊、多账号并发、可访问图片的真实理解、语音、反讽和方言、严重危机场景、多月自然交流分布，以及用户本人最终确认的口吻适配。固定对方续聊只能检查助手如何处理新观察，不能证明对方因候选消息而回复、采用了建议或关系更近。
