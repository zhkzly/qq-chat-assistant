# 独立的历史节点回放

固定同一份节点前的原始历史、切点、目标和新输入，让不同版本的助手自行构建记忆、组织上下文并回答。旧版本的派生记忆不作为新版的输入；数据库和记忆架构允许重写。

案例、评测运行器和评价标准不依赖产品源码。当前产品的接入代码单独放在适配器中；更换架构时主要调整适配器。内部检索、记忆和模型轨迹用于归因，不要求必须执行某个固定工具调用才算回答正确。

```bash
npm run eval:replay:list
# 走实际产品链路，但模型响应是合成占位；只验证接通。
npm run eval:replay -- --id conv-reconnect-known-anchor --out /tmp/qq-replay-example
# 显式使用当前选中的真实模型，最多12次HTTP调用，含记忆准备等。
npm run eval:replay -- --id conv-reconnect-known-anchor --live --max-http 12 --out /tmp/qq-replay-live
```

输出目录必须不存在。每个场景使用独立数据库，场景内保留实际助手回复与状态，继续接收后续输入；历史中已经发生的助手回复只作为归档背景，不重新生成。当前接入会先用真实记忆维护构建本版记忆，这属于受控历史准备，不代表自动调度已经通过验收。没有修改真实QQ、用户数据库或模型设置。

- `manifest.json`：数据、标准、代码与运行版本，执行状态及未执行场景。
- `*.run.json`：逐轮实际输入、输出和可选内部诊断。
- `*.review.json`：给评审看的背景、实际回答与标准，不含内部诊断；评分默认未填写。
- `transport.json`：实际模型请求、响应和总调用次数。

原有18个基础案例和3个历史回放场景保留，新增17个场景，共38个场景、81个步骤。旧案例中带解题提示的目标、依赖特定旧回答的反馈，通过版本化文件明确记录调整，保留原文，不偷偷换题。人工写好的“正确理解”仅供评审，不提前喂给助手。

评价先看建议能否解决当前需要，再根据轨迹查接入、记忆、检索、上下文或表达中的偏差。运行完成不等于回答合格；虚构的对方后续也不能证明建议促成了回复或关系升温。这不是实际桌面QQ集成验收。

完整协议与证据边界见 [REPLAY.md](REPLAY.md)。真实历史快照应留在本地私有目录，不能提交Git；仅按消息时间筛选今天的数据库，不能保证恢复后来被编辑或删除之前的真实状态。

本轮修复了历史便签日期／类型恢复、长来源分段进展判断及回答内容遗漏。新协议可绑定本轮真实回答后继续反馈，也支持目标变更、来源停用／删除和已发生的QQ撤回；都是隔离环境里的外部观察，不会操作真人QQ。

批量回放可显式使用 `--continue-on-case-error`，保留失败并继续其他独立场景；默认遇错停止，总调用上限始终有效。失败场景及未执行步骤不会被填成通过。

覆盖范围与压力输入见 [覆盖表](COVERAGE_CN.md)。`npm run eval:judge:check`、`eval:judge:export`、`eval:judge:compare` 用于评审参照与真实评分对账，不自动调用评审模型。参照仍是AI编写、未由用户确认的开发材料；语气尺度分歧需保留。
