# Memory and context stream challenges, v1

`memory-context-v1.jsonl` adds twelve visible fictional primary-evaluation cases in six contrast families. It is separate from the four-case adapter pilot and from the legacy regression dataset. All cases start empty and contain only supported external events; every new assistant message must be generated by the running implementation.

| Family | Cases | Main question |
| --- | --- | --- |
| `stream-control-scope` | local / recurring | Does a scoped old instruction remain scoped while a clear current intent change is honored? |
| `stream-proposition-holder` | third-party / first-person | Does implicit later help keep a report's holder distinct from its utterance speaker? |
| `stream-private-disclosure-scope` | withheld / permitted | Does a current disclosure instruction and its continuation control authentic outward wording? |
| `stream-closed-topic-current-choice` | closed / reopened | Can a local task stay closed, yet genuinely reopen under current human choice? |
| `stream-long-source-control-position` | head-veto / tail-veto | Does the same current scope survive a long source with the control at different positions? |
| `stream-long-discussion-query-frame` | implicit / explicit recall | Can actual long private consultation preserve earlier facts, time and disclosure scope under different final query framing? |

## Source and adaptation boundaries

Seeds come from project-local fictional raw histories, with exact source-file SHA-256, source case and raw IDs. The notebook body and the long-discussion user accounts are retained verbatim. Source metadata does not assert that every new event is an original quotation: each case's adaptation declares reauthored clocks, additional external observations and ordinary user requests. No source assistant answer is restored. In the long discussion, the twenty source context accounts become five groups of actual new user requests; headings retain their original report dates.

The privacy pair changes permission and desired expression together through one current human disclosure instruction. The attribution pair changes the asserted holder together with its explicit complement. These are declared semantic factors, not claims that wording surface is otherwise identical. The closed-topic pair changes the final requested topic. The two long-source cases preserve the same body and control text and change only control placement. The long-discussion cases share history, latest QQ and permissions and change only the final query framing, without supplying the answers in that query.

All reviewer criteria are provisional development criteria. Multiple useful phrasings and strategies remain acceptable. Expected profiles, labels, criteria, family names and seed descriptions stay outside `runtimeCase()`. An internal lookup, memory shape or compression trigger is never a passing condition.

### Pre-freeze review clarifications

The control-scope pair tests honoring a current override and avoiding overgeneralization. Its second request lies outside the stated activity condition and its third explicitly overrides the earlier choice; the pair does not establish positive retention of a recurring instruction.

In the privacy pair, the existing meeting arrangement is supported by the QQ question and the user's confirmation that time/place remain unchanged. Confirming that arrangement is permitted in both variants. The prohibition on invented promises concerns new or unrelated guarantees, not that supported meeting.

The long-discussion pair is anchored long-history/query-framing recall: the latest QQ explicitly mentions the webpage and Saturday. It is not evidence about cue-free retrieval or retrieval without surface overlap. These clarifications changed only reviewer metadata and this documentation; runtime events, texts, goals and hard histories remain unchanged.

## Size and lifecycle

The corpus contains 42 actual user-request events. Eight short cases have three requests each. The long-source cases have two requests each and a 46,835-byte maximum user request; each preserves the entire original 15,617-character volunteer notebook. The long private-discussion cases have seven requests each and a maximum single user request of 9,988 bytes, with more than 12KB of older private text available to the product's compaction planner.

These sizes create an opportunity to observe deterministic source degradation and model-based private-discussion compaction separately. Only actual run diagnostics can establish which path was exposed; text size or a green input validator does not prove that compression ran or worked. Explicit idle intervals allow ordinary scheduled maintenance; incomplete work remains observable, and no force-maintenance action is part of a case.

Sequential streams do not establish in-flight concurrent ingress, desktop behavior, restart persistence or causal adoption of generated wording. Fixed self/contact events are independent external observations. Families and their source histories must remain together in any later split; these visible cases are not unseen holdouts or human gold.

## Offline check

```bash
node scripts/eval-stream-replay.cjs --cases evals/assistant-stream/extensions/memory-context-v1.jsonl --check
```

The check loads no provider. It validates chronology, IDs, event kinds and declared source hashes/IDs. Authoring and validation records are in `docs/goal-memory-iteration-20261105/challenges/`; the authoring helper can reproduce the JSONL, but must not be rerun over a frozen run's source dataset.
