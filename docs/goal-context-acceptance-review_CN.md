# 上下文整理与批判性验收

本次目标是让助手围绕双方愿意发展的恋爱关系，提供有依据的讨论、选择和表达。验收检查实际输入和输出，不以功能测试通过替代关系效果。

已修复：规划解释丢失；没有保存话题时临时分寸无法交给成稿；关系方法只有目录而没有操作指导；已批准经验换一种说法就难以召回。另补了可选原文检索的共同限额与相关性顺序、准确时间与程度表述。

讨论与成稿现在分别保留。用户问依据时，应解释实际原话、当次意思和做法对相互了解等目标的作用，不能只复述禁令。成稿只收到获准意思和简短控制，私下理由不会变成可发送材料。

471 项功能检查通过。解释与图片各 5 项浏览器检查通过。真实模型使用本机当前配置的 gpt-6-sol 和虚构记录，四个有边界的执行块共 32 次 HTTP 请求；模型、配置和来源快照未被悄悄替换。

第一组 11 场景中，审查保留了“玩点”被加强成“平时主要玩”和无依据的“这么晚”两项问题。补充事实范围和本机显示时区后，定向复验修正；时区不能用于猜用户城市、距离或她的所在地。首次依据补测出现 HTTP 408，未算作通过，另一个场景因此跳过；只补测未完成项的记录也单独保留。

依据场景还出现审查分歧：一位认为来源与当次限制的说明已经足够，另一位认为缺少对长期目标的积极作用。采用更严格标准补充说明后，最终回答明确指出“回应她说的内容，也给以后慢慢了解留空间”，同时不预测她的好感，两位审查者均认可。

新意图覆盖旧约束也做了反向检查：直接询问游戏名、明确询问项目进度与吃饭两个问题，都保留在实际稿子里。原来的少追问经验没有变成永久禁令。

限制仍保留：来源合法不等于语义正确；这组虚构案例不证明陌生场景都可靠，也不证明她会喜欢用户。经验案例同时含词面重合和近期讨论，不能证明 fallback 的独立因果效果。以前的理解有一部分通过种子记录提供，验的是交接而不是完整自主形成。

桌面启用与数据保留结果会在实际执行后补充。真实聊天、图片和凭证不进入本验收文档。
