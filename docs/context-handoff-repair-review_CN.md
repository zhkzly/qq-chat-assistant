# 上下文交接修复与快速决策边界

本次修复针对两个已复现问题：普通压缩重新吸收自动分析，以及有据核心表达偏好未完整投影到受限成稿。修复不新增用户配置步骤，也不将聊天建议变成自动发送。

## Jev 是否参与

QQ助手没有独立的Jev调用链。当前职责如下：

| 环节 | 实际承担方 |
|---|---|
| 当前交流、近期时窗、预算、来源有效性与候选过期 | 本地确定性代码 |
| 旧资料初步召回 | 本地词项与中文二元词的BM25式检索 |
| 理解本次意思、选择可聊内容、必要时决定补查 | 当前配置的主模型 |
| 最后表达、讨论压缩、后台记忆整理 | 同一当前模型的不同阶段与预算 |

因此存在快速本地筛选，但尚无Jev语义路由、Jev相关性评分或学习式记忆控制器。模型代理背后的内部实现未被独立核验。开发工具中安装的`fast-jev-compaction`只说明开发环境具有该插件，不证明QQ应用调用它。

这次不接入新的Jev服务。是否增加语义快速筛选，应以本地召回确实遗漏相关旧事、主模型反复为简单选择消耗明显时延等证据决定，并验证更正和反证不会被筛掉。不能用长期目标“拉近关系”单独给全部历史打相关性分。

## 需要保持的两条边界

自动产物可以作为明确引用的生成对象供用户解释或改稿，但不应默认进入普通私下讨论压缩。压缩协议和缓存需同步失效；改变选择政策不能删除原始用户记录或合法的旧引用产物。

表达偏好需要一个统一的安全投影，覆盖note和有据核心记忆，并核对主体、来源版本与适用性。表达控制只携带简洁规范化要求和来源引用；不把私人理由、对方喜好或用户经历变成待发送素材。原始控制依据保留在本地，撤回或更正立即阻止旧值继续使用。

## 验证与启用

最终功能、界面、实际模型虚构场景和真实桌面状态分别记录。此前泛问、机械回应以及未提供的心理经过仍保留在[既有审查](relationship-refactor-review_CN.md)中；本次交接修复不能自动证明这些措辞问题全部消失。

当前QQ进程未启用开发刷新探针，安全启用需要重建worker和controller。不得用旧实例方法替换冒充完整新版本，也不强制结束QQ或覆盖未发送输入。具体执行结果在修复验证完成后追加。

## 2026-10-17修复结果

- 自动产物按持久origin、完整作用域task ledger或精确作用域run统一分类。普通规划、压缩触发计数、选段、序列化和缓存校验共用该规则；未知来源不按文本猜。旧协议缓存不复用，明确选中的生成对象仍可解释和修改。
- 原始可引用轮次与普通可压缩轮次分开。另修复了旧origin回填改变原始指纹、随后普通写入误删合法解释的问题；识别自动来源现在不改写原始记录。
- 核心表达偏好与note/界面要求共用安全投影。新增主体、转述、来源修订、多来源、条件、过期与更正检查；覆盖用户原有“别太直白”表达及其同义摘要。控制来源进入manifest，私人原文和理由不进入成稿素材。
- 最终92个测试文件、620项功能检查全部通过，递归语法及连续合成浏览器检查通过；没有发送QQ消息。新缓存边界为`relationship-context-2026-10-17.1`，压缩协议同日升级。
- 三个已声明的虚构模型场景只发起一次连接尝试就停止，未得到provider响应；后两例未运行。只读探测确认`127.0.0.1:8317`没有监听，`GET /v1/models`为`ECONNREFUSED`。这是未完成的模型验证，不能写成语义通过；未改API地址、模型或密钥来绕过。

机器可读记录见[修复证据](context-handoff-repair-evidence/verification.json)。本地SQLite已做一致性备份，仅保存在Git忽略的私有data目录，未进入这些证据文件或Git。源码准备合入main；实际worker启用和模型连通性仍分别核验。

用户随后启动8317代理，只读模型目录返回HTTP200且包含当前`gpt-6-sol`。在外部状态已恢复后，对同一组预声明场景单次执行，共6次HTTP、6个响应，三任务均完成规划与受限成稿；未触发额外修复，代码及配置在批内不变。首次连接失败原件保留，未把它覆盖为成功。此次保留完整的[四类合成工件](context-handoff-repair-evidence/model-restored-four-artifacts.json)：规划输入、已校验短指导、受限成稿输入、最终输出，便于以后定位表达偏差。

[实现参与者交叉审查](context-handoff-repair-evidence/quality-cross-review_CN.md)将邀请、适度表意判为采用，自我分享判为小改（开头明确指她的近况）；没有可证实的硬失败。它不是独立人际专家评审、未见泛化或现实关系效果，不能抵消原L4/H8失败。代码修复及新的有界证据支持集成功能链，措辞仍由用户检查与编辑。

## 本地集成

修复提交`583abe3`已在本地快进合入main；逐字节核对45个源码/UI文件无差异，实际导入版本为`relationship-context-2026-10-17.1`。main原有未跟踪的用户笔记、design和research未纳入或改写；没有推送远端。

当前QQ仍持有旧worker，因此源代码合并不等于应用已更新。已设置15分钟的一次性等待：仅在用户正常退出QQ后启动现有项目启动器；不发送退出信号、不覆盖输入。启动前再次核对源码，随后检查新worker版本、认证、原会话、原始消息数量及原生读取状态。运行状态只写入私有临时文件`/tmp/qq-handoff-launch-status-20261017.json`；若用户暂不退出则到期停止。本段记录启用安排，不把等待状态当作实际桌面验收通过。
