# 开发顺序与验收门槛

> 2026-10-12 上下文实现已在 `feature/relationship-context` 完成候选验证；当前五部分流程见 [上下文管理](context-management_CN.md)。以下保留原有 QQ 接入与快速回复架构/阶段说明，不代表新流程已部署到实际 QQ。

## M0：先证明“正常桌面 QQ + 只读接入”

以下为最初的阶段划分；当前已有原生安装和历史/窗口/草稿验证，完整新来信验收仍待现场观察。先选择用户已有 Ubuntu/QQ 的受支持插件启动方式，制作最小只读验证器，不先开发完整恋爱助手。

| 检查 | 必须保留的证据 |
|---|---|
| 同实例接入 | 正常 QQ 窗口仍能手动聊天；账户没有被另一客户端顶下线；记录 QQ、框架和适配器版本 |
| 当前联系人 | 在会话 A 点击入口得到可信 A 标识；切换 B 不误绑；数字 QQ 号可解析为正确 NTQQ UID |
| 旧记录 | 选定会话最近页与至少一个较早页的真实标识、时间、条数；说明可达范围和错误 |
| 双向增量 | 接收到对方来信；用户在 QQ 实际发送的文本被观察到；不以复制事件冒充发送 |
| 只读边界 | 无消息发送/转发/快速操作调用；采集接口不接受任意 action；其他会话不持久化、不进入模型 |
| 窗口生命周期 | 重复打开只有一个窗口/订阅；关闭后停止该会话新推理；旧事件迟到不串会话 |

M0 不通过时，记录具体失败的 QQ/框架版本、接口和症状，调整接入候选；不能改称导出导入方案已经满足实时需求。安装或修改现有 QQ 前，先准备可审阅的接入候选、影响范围和恢复方案。

## M1：自动历史与实时数据层

实现后台分页、增量游标、去重、乱序处理、覆盖状态和本地存储。以账户+对端隔离。仅保存指定会话。支持重连恢复，不悄悄跳过失败页。

## M2：辅助窗口与回复建议

QQ 入口打开窗口，自动绑定当前会话；可明确锁定其他 QQ 号。实现指示/语气、近期上下文与必要历史、3 条建议、编辑和复制。新消息自动更新上下文，用户正在编辑的草稿保持稳定。模型失败保留部分文本并标为未完成。

## M3：导出和个人偏好

增加 TXT/JSON 导出、时间范围筛选、经用户确认的偏好与事实、样例回放。HTML 和非文字消息在后续阶段处理。自动导入/加载仍是主流程，不要求用户先导出文件。

## 如何评估建议是否有用

用用户自愿提供的脱敏样例建立回放集，比较“只看最后一句”“近期上下文”“近期+相关旧片段”。记录样本数、采用/修改/放弃建议、重复或编造事实、串会话以及响应时间。先检查表达是否符合用户意图、能否直接使用，不用“恋爱成功率”作为未经验证的效果承诺。

## 第一版通过标准

M0 全通过；后台自动加载历史；双方消息持续同步；建议可以编辑/复制；导出保留覆盖信息；没有任何自动发送能力。人工复制与发送仍在原 QQ 内完成。

2026-10-12：已实施真实桌面接入，验证指定会话 739 条双向历史、完整浏览、入口自动绑定和只填草稿，57/55/13 个行为/故障注入/浏览器检查通过。经确认的个人事实、时间范围筛选、长期摘要和聊天目的/当天话题流程尚未实现；用户要求先完成现有 UI 修复。具体证据与开放项见 verification_CN.md。
