# 旧理解的停用与有界复核

长期理解应帮助用户找到真实谈资、理解当前处境并持续商量，也应能放下不成立的旧解释。例如，如果一条旧记录把“这次简短一点”误存成永久偏好，后台应能核对原话后停用它，不必为此编造一个相反的新偏好。明确保存的用户笔记、原始交流和纠正记录继续保留。

023 沿用[基于原文的理解](evidence-backed-understanding_CN.md)与同一个后台整理流程。正常输出可以直接停用已提供的旧条目；程序仍核对账号、联系人、条目版本及必要原文的完整范围和修订。停用不会重新要求一条错误旧偏好满足“创建永久偏好”的条件，也不能绕过创建新偏好的限制。原有事实日期保持原义，复核／停用时间另记；不为满足引用格式而加入无关的新问题。

来源日志处理完，不等于旧理解已经核对完。若仍有未核对条目，后台可在原有空闲、任务和调用预算内重读必要原文。一次有效复核仍未作出语义决定时，保留“理解待核对／暂缓”，不会伪报完成，也不会因时间变化或摘要改写反复调用模型。以后正常处理新资料时，仍可据实际原文解决旧条目。

原文不完整、已变化或无法放入预算的条目不算复核过。组合过大时先减少同时复核的条目；只有单条必要原文仍不能容纳，才记录相应暂缓原因。未提供的条目不会消耗它的复核机会。界面分别显示待整理的来源数、待核对的理解数，以及可复核／暂缓数量；用户仍可照常商量和手动复制发送。

这些约束和虚构旧库测试只能证明程序边界、历史保留与调度行为，不能证明模型对人的解释准确。实际记忆视图及后续帮助仍需按真实模型输出独立审核。
