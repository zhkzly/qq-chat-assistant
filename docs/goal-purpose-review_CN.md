# Goal 宏观目标与执行规则复审

2026-10-30，基于 `880165d` 修订为契约 `2026-10-30.2`。用户授权完善后启动 Goal；此记录描述配置与方法验收，产品优化的实际回放另行保存。

宏观目标是让实际 QQ Assistant 围绕用户的长期目的持续理解处境、辅助选择下一步、找真实可聊内容、主动联系或延续交流、支持自我分享和实际共同经历，并通过原始证据、长期记忆、当前状态、方法、有限上下文和反馈保持连续性。恋爱是当前具体目的，产品支持后来改变的目的。工程基础设施和固定集得分均不能替代产品能力证据。

## 本次变更

- 完整开发集仍为 38 场景／81 步，原始数据及标准未变。首批为两个实际出稿／反馈失败及缺素材、QQ 撤回两个反例，共 4 场景／7 步。
- 小批次限制实验成本，不限制完整因果修复的组件范围；移除实现技能中的最小改动倾向。阶段外已知冻结案例可作为守卫，仍须按原标准评分，不转成该阶段主目标。
- 新增按需架构审查职责及独立技能。设计与实现继承研究工具；架构审查可用相关 OpenViking 与一手网页资料检查组件消费者、权威、生命周期、反例和替代方案。归因者定位实际偏差，盲评者只判实际可见表现。审查者可以否定重构、新组件或局部补丁。
- 全局模型、提供方、审批与 hooks 不变。只读审查是角色指令，不声称为独立操作系统沙箱。新角色不进入产品运行时。

## 独立挑错与修正

受指派的架构审查发现并促成三项修正：完成条件须包含主动联系、持续商量到表达／行动和记忆／当前意图接续的实际证据；多案例 live 示例须显式继续保留首例失败后的其他场景；持久化结构改变时须补基线创建的虚构旧库升级验证。历史重建不证明迁移，42 条存档私聊也不自动证明真实持续商量。

审查同时指出：当前两条来源失败轨迹不支持先整体替换产品或新增规划器／向量库。初轮应辨别各自失败原因；必要的大改仍被允许。每侧 16 次请求是否足够仍须按内部准备与修复估算，缺失结果不得评分通过。

## 验证边界

- 25 项相关测试通过：4 项契约、16 项轮次证据处理、5 项角色生成；新增选样与跨阶段守卫检查先失败后通过。应用 JavaScript 解析、五个技能格式及生成一致性检查通过。
- 原生 Codex 的 prompt-input 实际发现四个专业角色。独立架构审查按指定规范实际读取源码与 OpenViking 历史理由并提出上述问题；该方法前向检查使用受指派的通用子代理，不能冒充原生具名角色派发或产品收益证明。
- 未修改产品 `src/`、`ui/` 或 QQ 插件；本次修订不声明新的产品质量、真人桌面或关系效果已通过。既有角色加载与评审记录仍是历史版本证据，不改写其摘要。
- 已读取用户 OpenViking 的 Context 管理和 Harness／Tool／Skill 设计资料。采用的原则是按下一决策选择上下文、区分记忆与任务状态、检查写入／选择／压缩／隔离，以及仅在独立职责需要时分拆 agent；这些资料作为设计依据，不能替代本项目实际验证。
