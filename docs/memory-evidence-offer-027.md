# Evidence-backed memory offer (027)

This candidate changes the background memory offer and typed admission boundary.
It does not change the operation protocol, model, scheduler, caller budgets, QQ
adapter, frozen cases, or manual copy/send workflow. Evidence below is fictional
zero-HTTP Store/wire testing and synthetic-boundary product integration, not a
desktop QQ test or a conversational quality verdict.

Actual candidate025 HTTP1 committed two English claims with empty topic keys.
Its HTTP4 Chinese question selected no prior claims, then added the complete old
Chinese original as `c1`. Consequently the model could not reference either old
record ID/version. Independent proposals citing that actually supplied old body
were subsequently rejected by a journal-membership condition. Permitting those
translated proposals alone would create duplicates; it would not demonstrate
that an existing understanding had been reaffirmed.

The normal Store batch now chooses its existing bounded window of six reviewed
originals before selecting targets. It resolves directly dependent record IDs
through `memory_dependencies`, with lexical and pinned navigation retained as
optional candidates. At most 24 target candidates are considered. Every writable
target is packed with its complete canonical provenance and available transition
decision provenance as one byte-budget unit. Adding those supporting originals
does not turn them into further retrieval seeds. A legacy distinct-successor
edge reads only the direct successor's canonical revisions, without recursively
expanding later transitions. Unavailable or over-budget support leaves an
explicitly read-only target, or omits it when even navigation cannot fit.

The wire reports `originalsDelivered`, `updateAuthority`, aliased
`decisionSourceIds`, and decision availability. Aliases and summaries provide no
write authority. Admission checks actual delivered bodies, full required ranges,
redaction, source revisions, account/contact, target versions, and the memory
snapshot. Missing decision support cannot revive an inactive target. Withdrawn
proposal text is not reconstructed. A genuinely new direct observation may
independently establish a new record while the old uncertain record stays
inactive.

An independently discovered fact from an old original is admitted only when all
of its old provenance roots were completely delivered in this request. An
unrelated current question cannot bypass that requirement. Current journal
segments retain their existing partial-evidence policy; semantic recovery has
no current journal sources. Source dates still own observation/report clocks;
reviewing a body does not freshen them. Distinct compatible propositions sharing
a source, subject, and aspect remain separate.

The full functional run also exposed an existing directory-read failure. Its
first cause was four empty foreign-scope reads, each creating a migration receipt
despite having no records. `knowledgeDirectory` now returns an empty validated
scoped read before migration when that scope has no knowledge. Nonempty legacy
rows retain the existing migration and repair path. The original no-write
assertion is unchanged; the same failure was retained from frozen025 for
attribution.

`tests/fixtures/memory-evidence-offer-025.json` preserves the actual fictional
HTTP1 proposal and HTTP4 inputs, bound to the earlier transport SHA-256.
`tests/memory-evidence-offer.test.cjs` first reproduced five failures out of seven
checks on the unmodified predecessor. Expanded checks separately cover offered
old IDs, explicit reaffirm/no-change, newly noticed old facts and events, body
and scope negatives, unchanged evidence dates, compatible facts, mixed old/new
batches, decision withdrawal, fresh direct support, direct successor evidence,
and an exact atomic byte boundary. These scripted choices do not predict the
selected model's actual identity or transition choice.

Local artifacts are under `.goal-runs/memory-evidence-offer-027-zero-http/` and
`.goal-runs/memory-evidence-offer-027-synthetic-final/`. The earlier shared-cap
synthetic batch remains under `.goal-runs/memory-evidence-offer-027-synthetic/`;
it stopped at the unchanged 16-request cap, retaining its error and unexecuted
cases. Final independent synthetic guards each retain that same default cap.
All semantic review fields remain ungraded. A selected-model comparison and its
independent actual-output review belong to the coordinator.
