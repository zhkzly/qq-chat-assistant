# 按需上下文与当前候选回复

目标是帮助用户回应真实分享、表达自己的真实内容、逐渐相互了解，并在合适时考虑共同活动或表达好感。候选回复是可修改的参考，实际发送始终由用户在 QQ 完成。

## 信息组织

- **常驻小集合**：当前请求、固定观察时间、当前相关的完整交流、仍有效的局部方向与最新纠正，以及已确认表达偏好和少量有据的长期核心。保留来源和日期，不把临时纠正或助手推测升级为长期事实。
- **近期默认层**：最近72小时的实际QQ和用户主动私下讨论默认进入候选，当前即时交流独立标明。72小时是工程默认值，未被证明比其他范围更优；它不是无限量原文注入许可。按完整交流段及总预算装载，超过时提供遗漏范围和取回原文的入口，复用已有讨论压缩。
- **按需背景**：更早的人物事实、共同经历和可分享素材通过相关性或显式lookup加载。保留原始来源与日期，不用旧档案填满剩余预算。
- **轻量导航**：较早讨论和记忆只提供有界线索；需要精确内容时使用已有 lookup，再加载对应原文及必要相邻消息。
- **压缩与外置记忆**：已有讨论压缩和后台记忆维护继续使用。原始聊天不删除、不改写；摘要不升级为事实或分享权限。
- **受限成稿**：只传获准内容、相关实际 QQ、短方向控制及程序投影的表达偏好。完整私人理由和长期追求目标不进入成稿输入。

预算是上限，不是填充目标。字节预算用于确保完整请求可传输；它不是经过模型 tokenizer 验证的上下文 token 数，也不是质量提升的证明。

## 自动帮助与连续交流

新来信稳定后，自动入口优先生成一条完整可编辑候选；存在有实质差别的方向时可给最多三条。方向可以是接住分享、轻松反应、真实自我分享、了解一点或共同活动，不固定为“认同＋追问”。分析折叠在当前候选之后，复杂意图仍可进入私下商量。

没有候选时必须区分：实际已处理或需暂缓（wait）、需要决定内容的用户事实（clarify）、生成未交付可用候选（unavailable）。结构合法不能证明语义判断正确；连续场景与人工语义复核单独验收。缺图或不知花名等非关键缺口，可以提供不依赖未知细节的表达。

本人实际发送使当前应答候选失效；对方后续来信重新生成。未发送的编辑文字保留。关掉自动建议时停止自动工作，用户主动发起的私下请求保留。自动观察产物保有来源记录，但不会作为用户的新意图反复灌入上下文。

## 依据与边界

[Anthropic 原文](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)支持有限必要信息、轻量引用、即时检索及预载与探索的混合方式，也指出过度压缩可能丢掉关键细节。本文将这些原则映射到当前交流、旧聊天、局部纠正和成稿交接，不引入新的多代理运行时。

[Lost in the Middle](https://arxiv.org/abs/2307.03172)研究长上下文信息位置对特定检索与问答任务的影响，不能据此宣称本项目缩短输入后一定更会聊天。

[Jev-Mem](https://arxiv.org/abs/2609.23986)将高频记忆组织和检索控制与最终推理分开。本项目复用本地筛选、现有检索及有界lookup承担前者，没有宣称接入Jev学习式控制器，也不因使用双系统名称就增加每条消息的模型调用。

[fast-jev-compaction](https://github.com/tamaratran/fast-jev-compaction#how-it-works)采用选择式压缩：批量判断工具调用与结果是否保留，留下的内容保持原文。它不从输出中删除用户或助手文本，因而不能直接用于筛选QQ纯聊天；可借鉴的是有界候选、保留决策与原文回取。当前目标“拉近关系”过于宽泛，不作为唯一相关性依据；与旧理解冲突的新事实、改口和纠正必须保留。筛选质量、输入长度与最终聊天质量分别验证。

## 验收要求

功能验收检查顺序、相关性、来源、偏好交接、过期取消和作用域。界面验收检查当前候选可见、旧候选不可作为当前候选采用、输入保留。虚构连续模型案例单独检查是否真正给稿、是否机械重复、是否偏离最新意思，以及是否编造事实。所有模型失败与条件通过均保留，实际桌面启用另行核验。
