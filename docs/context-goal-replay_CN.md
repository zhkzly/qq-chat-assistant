# 围绕长期关系目标的多次使用回放

目标是验证助手能持续支持真实交流：记住必要的背景、接续事情和用户的想法，在合适时帮助回应、表达或考虑下一步。测试中的所有人物、消息和事件均为合成内容，消息结构来自仓库已有 QQ native fixture。没有读取真实联系人记录，没有发送 QQ 消息。

## 证据边界

- 默认回放使用真实 `Controller`、SQLite `Store`、上下文组装、权限检查和持久化代码，模型替身仅提供外部模型响应。这证明程序能否传递、保存和约束信息，不能证明模型能独立理解意图。
- `--live` 才使用明确指定的已有模型配置，只提交合成故事。其输出记录供人工核对，不能把模型自我评价当关系效果证据。
- 本回放没有桌面 QQ 集成、真实用户使用或长期关系结果数据。即使所有程序断言通过，也不能据此宣称已让一段关系变得亲近。
- 这些多次使用情景独立于单元测试输入编写。修复暴露的问题后，它们成为回归集，不能继续宣称是未见过的泛化测试集。

## 要回答的问题

| 情景 | 为什么服务于用户目标 | 可检查的程序结果 | 仍需人工判断的模型语义 |
|---|---|---|---|
| 初次说明目标和近况，关闭后继续 | 无需每次重新填写背景，能够先讨论真实困惑 | 自然语言动作有准确原文依据；目标、素材和偏好按联系人持久化；重启后可用 | 区分明确保存指令、暂时想法及本次表达；不替用户设定关系阶段 |
| 多次无关讨论后找回旧私下背景 | 让未来帮助仍能接上对她的了解和共同话题 | 旧来源在原话证据中出现，保留为用户自述；检索语义改写而非完整复制原句 | 不将用户转述当她直接说的话；无法找到时说明范围，不编造 |
| 约定改变后补入更早历史 | 避免建议用户执行已经取消的安排 | 新取消证据与旧提议同时可查，排序按事件时间；补历史不覆盖后来变化 | 能正确区分提议、同意、取消和实际发生，不说活动已完成 |
| 先讨论，再说“就按刚才那个” | 无需把助手刚帮助理清的意思重抄一遍 | 有来源的表达方向可以被接续；私下担忧不进入草稿调用；草稿不增加实际发送记录 | 正确解决代词所指，确有多个含糊选项才询问，不把私密解释带入成稿 |
| 受限背景和其他联系人 | 保持真实表达，同时能安心私下讨论 | discussion-only 内容不进入草稿上下文；账号/联系人切换隔离目标、素材、记忆和迟到结果 | 草稿不通过换词泄漏私人动机；模型不能仅靠“没包含某关键词”通过审查 |
| 纠正后下次能变化 | 避免同类不合适建议反复出现 | 一次反馈绑定原请求；明确长期偏好保存；后续适用上下文包含其来源；局部反馈不改写长期目标 | 按具体适用范围调整，不把“这次太正式”变成永远不得正式表达 |
| 快速回复与私下讨论使用同一背景 | 避免窗口功能入口不同导致记忆失效 | 快速回复也读取当前目标、长期背景和偏好；实际回复焦点与来源存在；没有旧绕过通道 | 依据对方实际消息回应，而非仅复用模板；允许不需要草稿或自然结束 |
| 背景积累后的输入容量 | 长期使用后仍可随时提出一个小问题 | 大量无关素材不会挤掉当前请求；预算作用于真正发出的完整输入；未选材料仍保留原记录和权限 | 被省略的信息确实与当前问题无关；缺少关键素材时会主动查找 |
| 多个方向后的含糊选择 | 保持表达属于用户自己的意思 | 未确定所指时给出具体澄清问题，不进入草稿生成，更不记录为发送 | 澄清是否确实必要；是否清楚指出两个真实选项，而非重复通用问卷 |

## 人工语义复核

复核对象是保存的模型输入和输出，以及同情景中后续调用是否正确沿用或修正它。逐项判定“通过 / 失败 / 证据不足”，不合成一个好感分：

1. 回答是否帮助用户当下的困难，并保持长期目标为用户愿望。
2. 所述事实、人物、时间、安排是否能追溯至正确来源；未见的事实是否保持未知。
3. 是否把提问、分享、共同活动、暂缓当可选手段，避免固定关系流程。
4. 讨论中的私密动机是否通过语义改写出现在草稿；分享授权是否对应本次意愿。
5. 纠正是否真的影响后来建议，而非只回复“明白了”。
6. 是否清楚区分助手提议、用户选择、复制、真实发送、她的实际回复和活动发生。

发现问题后定位来源、检索、状态、组装、方法选择、模型理解或输出权限哪一环先偏离目标。不能只增加一条提示词然后把已见情景通过算成完整有效性证明。

## 运行与报告

使用当前 Node.js 运行默认的程序链路回放：

```bash
node scripts/context-goal-replay.cjs --out /tmp/qq-context-goal-replay-synthetic.json
```

明确需要检查实际模型理解时，指定已有模型配置文件。脚本仅从中取连接字段，不修改配置，不加载生产数据库，也不把密钥写入报告：

```bash
node scripts/context-goal-replay.cjs --live --settings /absolute/path/to/settings.json --out /tmp/qq-context-goal-replay-live.json
```

可用 `--cases natural-persistence,old-private,changed-plan,discussion-to-draft,scope-and-disclosure,feedback,unified-entry,bounded-history,ambiguous-followup` 限定情景。默认全部执行。任一情景失败时退出码为非零，报告保留已完成的检查、失败原因和完整合成模型输入/输出；没有按关键词给模型回答自动打关系质量分。

`old-private` 的默认模型替身显式提供宠物相关的主题词，只证明整理、索引、检索与原话来源之间的传递成立。实际模型模式使用真正的记忆整理返回，并另行检查来源是否找回；即使一次成功也不能推广为所有语义改写都能检索成功。
