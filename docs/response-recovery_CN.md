# 结构化输出失败时继续提供帮助

本次改动服务于同一个目标：帮助用户与网上认识、有好感的女生发展双方愿意的关系。私下讨论的主要产物是能帮助用户决定、理解或表达的回答；可选的背景整理失败，不应让一次“怎么继续”只得到 JSON 错误。能够继续回答，也不等于正确理解了用户的方向或能保证关系进展。

本文对应 `relationship-context-2026-10-13.2`。本次问题在已选 `claude-sonnet-4-6`、`http://127.0.0.1:8317/v1` 兼容代理上出现，修复没有更换模型或目的地。此前 [.18 整理发布的失败记录](discussion-compaction_CN.md) 仍保留；本文说明后续恢复路径，验收记录见 [恢复证据](response-recovery-evidence.json)。

## 按回答阶段恢复

用户遇到的故障是：讨论输出包含不允许的话题字段，既有修复又返回无效 JSON，虽然两次 HTTP 都成功，最终没有交付帮助。旧失败路径未保存完整请求阶段记录，不能据此还原当时所有模型原文。此次增加失败阶段的诊断记录，并按阶段使用原有的一次修复机会。

| 本次阶段 | 结构化结果无效后的处理 | 不扩大什么权限 |
|---|---|---|
| 私下讨论、回顾，以及可返回私下建议的“接着 QQ 聊” | 用同一模型、当前原始输入重新生成自然文字；这是既有一次修复，不是额外重试循环 | 不把失败输出中的操作、话题、人物理解、经验候选或状态更新写入记录 |
| 表达准备 `draft_prepare` | 继续要求结构化、可验证的来源计划；没有通过就不进入对外成稿 | 不用一段流畅文字代替分享授权或来源校验 |
| 已完成准备的受限成稿 `draft` | 只用受限输入重新生成一条完整、可编辑的参考表达 | 不重新加入私人目标、完整讨论、原始反馈或私人动机 |

恢复调用不带先前失败输出作为范文，也不尝试从坏 JSON 中捞出一句话当作有效答案。私下恢复最多6000字符；受限成稿最多1200字符且须为一条完整表达。空白、明显机器格式、超长或模型报告截断的恢复结果仍会被拒绝。长度与格式检查不能判断一句话是否自然、是否忠实于用户意思。

受限成稿保留原有素材和来源校验：实际 QQ、明确允许的素材、选定候选及有来源的短表达控制才能进入该阶段。模型仍可能误解这些控制，因此用户继续拥有检查、修改、拒绝和不发送的决定权。软件不增加任何 QQ 发送能力。

## 建议已交付，背景仍可能待整理

私下恢复只保存这次自然语言回答及程序生成的恢复标记。该路径不提交尚未应用的人物、话题、经验或工作状态提案；没有依据说“已经记住”“已经更新方向”。如果前一个有效阶段已经执行了明确用户指令，其真实操作回执会保留，不能因为后面的回答采用恢复路径，就声称这些操作被撤销。

界面在私下回答下显示“已先给出建议；部分背景整理未完成。”，不给这段私下文字增加“采用到草稿”捷径。需要对她说的话，继续明确请求表达，经过准备和受限成稿。受限成稿恢复则显示“表达参考 · 请核对”，可以按原流程编辑、复制或填入未发送的 QQ 输入框。

已有当前话题时，最近一次私下恢复会让话题区临时提示“这次想法待核对，以最新原话为准”。这只是界面提示，不是长期偏好或永久关系状态。后续普通回答或切换会话会改变该提示；是否完成背景审阅，仍由下面的来源回执决定，不能仅看提示消失。

忙时仍可选择下一次帮助方式、编辑未提交输入；恢复过程不修改正在运行的用途、不自动提交新输入，也不更换账号或联系人。

## 保住尚未整理的当前意思

如果用户说“这次不要邀约”后获得私下恢复回答，旧话题可能尚未更新。系统不能在下一次“那给一句”中仅凭旧方向继续邀约，因此单独保留待审阅的用户来源：

- 程序标记只绑定当前真实私下用户原话或规范化反馈及其来源版本。自动“接着 QQ 聊”的临时请求不建立用户私下目的；其 `intentSourceIds` 为空。
- 组装后续上下文时，最近3条待审阅来源优先保留原文，最多提供最近8条待审阅引用；其他遗漏计数明确记录。未载入的引用标记为需取回，普通讨论可按原始 turn ID 补查，反馈另标记准确被评价对象是否可用。
- 有效当前话题标为需要复核。最新原话、明确纠正和本次限制优先；待审阅标记本身不是外部事实、分享授权或稳定偏好。
- 只有实际成功应用的状态审阅或话题更新，才生成绑定来源版本的 `privateReviewReceipt`。回执随助手轮次持久保存，不依赖只保留最近12次的运行记录。读取时还必须与当前来源哈希一致，旧回执不能消除后来更正的意思。
- 来源已更改、删除或不可用时，不继续使用旧版本标记；旧记录缺少哈希则保守标为待核对，无版本绑定的回执不能宣称处理完成。

这份待审阅清单连接自然回答与背景更新，不替代 [长期记忆](context-management_CN.md) 或 [长讨论整理缓存](discussion-compaction_CN.md)。最新受保护原话本身过大时，系统仍可能拒绝超限请求；不会静默截掉限制，也不会删除原始讨论。

## 调用、诊断与失败边界

压缩、普通回答、严格表达准备、成稿、恢复和传输重试仍共用每次帮助默认4次 HTTP 的上限。一次普通私下恢复常见为2次请求；准备成功、最终成稿格式失败再恢复常见为3次。已有压缩、补查或传输重试会占用同一额度，不能承诺所有组合都在额度内完成。

默认选材预算仍是48,000 UTF-8字节，完整序列化文字请求上限64,000字节，包括 system、封装和 JSON 转义；这些不是 token 数。恢复也按实际请求重新检查，必要时重选可选来源，不能靠绕过预算或扩大私人资料范围完成。模型、目的地和当前会话授权保持不变。

失败时保留各阶段正常输入、清单、修复原因及调用状态；不把无效模型输出正文额外写入普通失败诊断。HTTP成功、结构校验成功、可读帮助交付和背景更新成功分别记录。网络故障、恢复再次不合规、严格准备失败、来源或会话变化以及预算耗尽，仍可能终止请求并保留用户输入。

## 已有证据及不能据此声称的效果

首轮 v1 回放使用虚构 QQ 与私人素材，通过真实 Controller 混合注入格式故障和调用真实 Claude：记录6次调用额度，其中3次是真实 HTTP，其余为测试注入。没有读取真实聊天或发送 QQ。它证明了故障路径可交付、受限成稿不含私人哨兵、调用没有越界；**私下建议与后续回顾的语义没有通过**。

具体负例应保留：

- 用户要求不问游戏名字，恢复建议却附加“最近在玩什么”，再解释为没有问名字；这种等价追问仍违背本次意思。
- 建议引用“我在这里卡了四十分钟”，原始素材没有这段经历，不能因为写在示例里就当作用户说过。
- 用户选的是“从与人较量转为解关卡”的温和反差，后续回顾却改解成设计者与玩家的难度落差，虽然产生了有效审阅回执，理解仍然有误。

同一轮的受限恢复给出“从跟人对打到自己解谜，这转变挺大的哈”，是一句完整、没有邀约或问名的参考表达，但语气较平，不能据此宣布自然度或关系效果达标。13.2提示补充了事实依据、等价限制、选定含义和不默认追加问题；改了提示本身不等于这些语义问题已解决。

13.2的 v2 使用同样的混合故障回放，仍为6次额度记录、3次真实 HTTP，各任务分别2／3／1次；运行前后源码哈希一致。分阶段复核结果如下：

| 阶段 | 具体结果 | 结论与限制 |
|---|---|---|
| 私下恢复 | 不再问具体游戏名或邀约，但补出“被机关卡半小时”的场景并问感受，另一句调侃“自己太聪明了没想到这么简单的事” | 可读帮助交付；预设经历的问法和针对聪明程度的调侃仍不适合直接认定为自然、妥当。初始只有含糊的“人与关卡反差”，没有选定助手候选原文，不能用后来才明确的含义倒推它此时违背了一个精确选择 |
| 受限成稿恢复 | 在用户已明确“与人较量改成解关卡”后，给出“从跟人打到跟谜题较劲，这转变挺大的。” | 本例完整、可编辑，无问名、邀约或虚构本人经历；最终输入没有私人哨兵。措辞较平，不代表吸引力或关系效果已验证 |
| 后续正常回顾 | 明确解释为“跟人较量”转成“跟谜题／关卡较劲”，保留不问名、不邀约，遵守先不写新句子 | 本例正确接住最新澄清；这是正常结构化回顾，不是第三次纯文本恢复，也不能把一次正确理解泛化到所有讨论 |

随后在同一8317代理上用 `gpt-6-astra` 对照同形合成案例，仍为6次额度记录、3次真实 HTTP，任务分别2／3／1次，运行前后源码哈希一致。私下恢复给出“哈哈，这是从跟人斗智斗勇，改成跟关卡斗智斗勇了。”，没有追加问题、虚构经历或针对智力的评价；受限恢复为“这是从跟人斗，改成跟关卡斗了。”，最终输入同样不含私人哨兵。回顾正确保留最新含义，并明确不问名、不邀约只是本次安排，记录不能证明参考表达已发送或她已回应。这一次对照中，Astra的私下建议比Claude v2更贴合温和接话的要求；两句最终表达都较简朴。单个案例不构成模型总体排名、稳定成功率或恋爱效果证据，对照也没有改变实际配置。

另一次针对先前失败请求的隔离复验，用1次真实 HTTP 得到正常结构化讨论，来源与当前输入保留。它不是触发恢复路径的证据，没有写回生产会话，也未据此评价真实关系或整体自然度。实际配置仍为本机8317代理上的 `claude-sonnet-4-6`。

候选版本的349项功能测试及31项当前浏览器检查通过；其中恢复专项浏览器为3组，覆盖提示、私下无采用入口、受限草稿编辑/手动复制、输入与模式保留、370×560布局及会话切换。专项的恢复标记来自合成服务端数据，证明界面行为，不证明后端生成、模型语义或真实桌面集成。具体回放、测试与发布阶段统一以 [恢复证据](response-recovery-evidence.json) 为准。

实现入口为 [阶段恢复与解析](../src/assistant-model.cjs)、[控制器提交与诊断](../src/controller.cjs)、[待审阅来源组装](../src/assistant-context.cjs) 和 [持久标记与回执](../src/store.cjs)。判断最终帮助是否有效，仍要检查具体意思、真实素材、表达分寸和用户实际后续；既不能用 JSON 通过率替代，也不能用她回复一次证明助手让关系更亲近。
