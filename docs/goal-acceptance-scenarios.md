# Predeclared relationship assistance scenarios

Declared before changing the UI or reviewing the new context/method implementation. These are fictional inputs and multiple answers can be acceptable. Their purpose is to test help for a mutually desired romantic relationship, not to measure or promise a romantic outcome. No fixed relationship stage, message quota, or hidden-attraction inference is required.

Each semantic review records the actual output, its supporting observations, unmet expectations, and any unknowns. Transport success and source presence are separate from this review. A fixture that supplies its own ideal model answer is pipeline evidence only.

## Independent acceptance boundaries

- The model receives the original account/contact-bound evidence, current request and local direction; drafts and assistant explanations never become actual QQ messages.
- Private planner rationale is displayed beside the editable draft but cannot be adopted as outgoing text. Whole-response feedback evaluates the exact displayed explanation and final summary, not a silently shortened artifact.
- Detailed methods and approved local guidance are observed in the actual request, with their applicable limits. Their presence is not proof they were followed.
- Missing history, refusal, uncertainty and sparse evidence remain valid outputs; successful romance cannot be inferred from a passed test.
- Synthetic browser checks prove input/display/copy behavior only. Live model review, if separately authorized, uses these predeclared scenarios and retains failures.
