# 整体重构的目标验收与独立反方提案

状态：设计与独立审查，不是实现完成报告。本文不修改既有 gold、源码或模型配置。依据为用户反馈汇总、当前消费链、已冻结的虚构场景及九个生成步骤的实际可见输出。

## 反方结论

需要重新明确“具体材料 → 此刻可说的意思 → 自然表达 → 实际收发后更新”的职责链。只把上下文变短、存储分成更多实体、输出变为有候选，仍不足以解决用户的“有内容可聊、逐渐亲近”。每一个新增组件都应指出：哪个实际消费者会因此选出不同而更合适的一句话；没有这个例子，就先不增加存储或模型调用。

“有话可讲”首先意味着：用户想联系或接话时，即便没有新鲜自我近况，也能从实际分享、尚未跟进的具体细节、共同话题、真实想法或合适活动中得到一个有内容的切口。它不意味着永远续聊、固定联系频率、每句追问，或越过对方明确的结束与拒绝。尊重当轮收尾与支持以后重新联系必须同时成立。

## 实际输出说明了什么

17 次 HTTP 产生七个虚构场景的九个生成步骤。独立可见输出审查为六步“采用”、三步“小改”，未发现预声明硬失败；逐维评分和具体依据保存在本机 `/tmp/qq-lazy-live-independent-review_CN.md`。评审者编写场景但没有编写被测生成实现，不是外部人际专家。

已有可用句子，包括司康反转、拼图装裱后接住新的打算、蛋包饭的具体工序、明确赶稿时的简短收尾，以及未知周日安排时私下核对。不能为了体现“展开”而把这些全部改成提问。

边缘输出也揭示了限制：“薄荷开始营业”主要是拟人换词；“蛋皮没破就值得满意”容易成为替她评分；“辛苦啦，待会儿好好休息”把具体善意事件导向模板关心与收尾。资料来源正确、没有连问、没有越界，并不能使这些句子自动达到本轮的主要目标。

本批没有验证：没有新来信或新鲜日常时仍能主动找到具体切口、连续多轮保持实质内容、用户本人长期语气适配，以及真实关系变化。实际发送失效的观察步骤在盲审文件中没有候选绑定快照，不能单凭该步 `reply=null` 证明生命周期正确；它需要另外的机械证据。

## 五类组件必须给出真实消费方

| 组件 | 应保存或投影什么 | 谁消费，怎样改变帮助 | 不应冒充什么 |
|---|---|---|---|
| 可聊素材与机会 | 她刚分享的具体情节、实际问用户的问题、尚未跟进的旧细节、用户有来源且可表达的材料、可选择的共同活动；带人物、时间、来源与已发生／计划区别 | 当前 planner 选择一个具体切口；所选内容进入表达任务。例：从“拼图完成”转到“已经裱好”，下一句就不再询问旧计划 | 不是“缺少 gameName 所以必须问”的槽位表，不是永远生成三个选项的任务，也不是默认新增的长期计划库 |
| 关系模型 | 双方说过的生活与偏好、实际共享事件、明确边界、相互交流的观察与反证；事实、解释、未知分开 | 帮助选择与核对材料，区分曾经、当前、计划与发生；例：过去书店工作可以作为历史故事，不代表仍在职 | 不做好感评分、隐含恋爱意愿预测或人格匹配结论；“温暖回复”不等于接受邀约 |
| 当前商量状态 | 当前想做的事、已选方式、局部避免项、用户纠正、未完事实与任务完成／关闭 | 限制本次机会选择与成稿；新意思改变时更新版本、撤旧控制、使旧候选失效 | 不是固定恋爱阶段；“这轮先别邀约”不能成为永久禁令；当前关闭也不等于长期 goal 结束 |
| 方法库 | 少量可组合操作：理解具体分享、相关跟进、真实分享、邀请、适度表意、修复或收尾；每种给正反例与适用范围 | 帮 planner 把材料变为可交流的意思，并帮助表达阶段保留选定机制。方法是否发挥作用由实际输出验证 | 不是按目录顺序执行的剧本，也不是多一张方法卡就多一种能力；没有消费者的新名词先不加入 |
| 评估与反馈 | 用户觉得哪里不合适、所评完整产物、真实编辑与收发分别记录；保留失败及条件判断 | 改进当前候选与可验证的局部经验；评估应指出材料、选择、规划、表达或生命周期哪一步先偏离 | 不能把复制当发送、一次喜欢某句升级长期偏好、对方脚本来信当现实效果，或把未报告硬失败当质量全通过 |

素材与机会优先是按请求形成的可核查视图。用户选中了某个方向，才有需要保存的商量状态；没有证据说明再建一套持久机会库会改善质量。它可以复用现有 sources、relationship、topic、workingState 与 lookup，不必先增加第二个服务或一个常驻模型。

## 规划与成稿需要交接“所选意思”

仅传“自然、简短、不要连问”容易留下通用认可。规划阶段应保留：这次具体想回应什么、选了哪个有内容的机制、用了哪些获准事实、还有哪个未知不能编。当前 `objective/allowedApproach/avoidances` 能表达这些内容时应先复用；不能只因想改进质量而再要求一组无明确判定语义的模型必填字段。

例如她说“队友都去找宝箱，最后我遛着 boss 跑了一圈”，方向可以是接她被迫救场的具体画面，或问队友后来怎样接应。它与“你平时为什么喜欢游戏”不同，也与只重复“全员寻宝队”不同。成稿必须保留这种具体机制，但无需输出私下的“为了拉近关系”。这仍需独立语义判断，source ID 存在只能说明可核查。

她若反问“那你平时玩什么”，有获准的真实用户材料时，应轮到用户自我表达；不能继续只收集她的信息。没有用户当前事实时，关键未知只限制相应自述，不使所有回应或素材选择停摆。

### 已实施的方法交付边界

方法库已在本地候选实现为 `relationship-methods-2026-10-16.2`，保留八个方法 ID 和公开 API。每族只有一份 canonical operation，紧凑目录与完整方法卡共用，删除了原先两套语义相近的长短 instructions。操作先说明怎样选择具体细节、真实分享或可执行表达，再说明本方法必要的分寸；共有的来源、权限和输出协议继续由阶段指导负责。

紧凑八方法目录为 2521 字节，指令长度 59–72 字符，保留原有小于 3000 字节及最多 90 字符的门槛。全库只有两个极简虚构教学例：椅子靠背装反后的具体跟进、口琴换气练习旧细节的主动回访。它们避开冻结七场景与 H8/H9 的具体题材；并不因此使 H8/H9 恢复为完全未见泛化集。

例子只在已选中的 `respond`、`choose_next_step` 完整卡中供给，紧凑目录和 `operationsFor` 不包含例子，回顾和成稿的默认选中卡也不包含例子。例子带 `fictional_illustration_not_task_evidence` 标记，不进入当前 sources，不能成为 outbound quote 的授权来源。压力回退可以丢弃完整卡和例子，但 canonical operation 仍须经紧凑目录或 system 到达模型。

新增 [方法交付检查](../tests/method-instruction-delivery.test.cjs)三项先红后绿，验证真实 `prepareAssistantRequest` 请求包含所选例子且计入序列化字节、伪用例子作来源会在受限成稿构建时被拒、压缩预算后必要真实来源和 canonical 操作仍在。结合原方法八项与指导三项，共十四项相关检查通过。这里是确定性功能证据，不是自然性或关系效果证明；本地源码冻结后的新实际输出仍由 root 统一计数并独立评审。

## 上下文和快速记忆控制的反方边界

长期核心可常驻简洁、来源有效的事实与确认偏好；72 小时实际 QQ 和主动私下讨论是近期候选；当前当轮仍要保留独立的时间与完成状态。候选窗口既不等于“全塞”，也不等于固定只留 N 轮。

在预算紧张时，完整来源、作用域明确的纠正及相关反证优先。可以取回一个冲突原句和必要相邻说话人／时间，不必强塞整段旧历史；确实没有取得的证据应有具体导航与局部未知。不能因为某个旧职业仍未知，就把对她刚分享的普通小事也变成核对问卷。

快速控制与主要推理分离可以先体现为本地快照、来源有效性、时间层选择、预算和可导航 omission。宽泛的“拉近关系”不能单独成为相关性查询，否则什么都相关。是否增加语义记忆控制模型，应由现有选择、relationshipPatch、更正链、近期完整片段与有界 lookup 的已确认漏例决定；多模型或多代理运行时不是此次目标的先验要求。

## 建议的验收顺序

1. **先保留当前差例与真实因果断点。** 九步实际输出的边缘项继续作为边缘项；先确认用户意图、素材、所选方向和最终表达在哪一步失去内容，不能把旧失败统一改名为“需要更大模型”。
2. **机械边界单独验。** 账号与联系人、原消息字符串 ID、来源版本、私下信息用途、最新时钟、候选与意图版本、实际发送失效、用户编辑保留、预算和取消都可确定性测试。此前负对照已证明单靠旧运输检查分不清好坏，不能继续拿功能总数替代质量。
3. **语义按逐步五维＋采用判断验。** 处境、意思、具体帮助、自然互动、双方选择各给 0/1/2 与输出依据；同时记采用／小改／重写及硬失败。不能平均掩盖 0 分，也不把每句有问号当作展开证据。现有九步保留原评分，新增目标另用独立场景，不回改 gold。
4. **连续轨迹覆盖主动与被动两种工作。** 原七场景覆盖接话、图片未知、实际发送、新来信、局部纠正、旧干扰、收尾和关键未知；独立 H8 覆盖无新来信、无新鲜日常时从旧具体细节重开；H9 覆盖普通分享的实质展开。H8/H9 只有定义和运输探针，尚无实际语义结果，不能计入通过分母。
5. **新增反例以行为为金标。** 她反问用户时能真实回答；用户最新改口解除旧限制；具体拒绝只限制对应行为；机会已完成后换切口；职业改口保留历史与新现状；未知用户计划不被画像补全。不要为了覆盖这些反例先扩充实体数量。
6. **对照用于区分原因。** 同输入同模型的 main／候选比较可以比较整体表现，不能独立归因提示词或上下文。需要诊断时再在少量已确认差例上分别固定模型与 prompt，比较当前／人工选定相关材料；或固定 composer，比较实际／正确短 guidance。只有相同合理输入仍普遍失败，才有依据讨论模型能力。所有额外实际调用由 root 统一授权和计数。
7. **最后验证真实应用消费者。** 合成 Controller、浏览器、实际模型虚构输入和真实桌面启用分开记录。新设计尚未合回 main 或刷新应用，不得把设计认可或模拟轨迹说成真实用户工作流已改善。

## 当前建议裁决

采纳素材／机会、当前商量状态、来源有效的长期记忆、规划表达及候选生命周期的职责分离；先复用现有数据与受限模型链。接受 context snapshot／policy／catalog／selection／planning-view／wording-view／budget-trace 的可测边界，但不把必须拆成七个模块当产品验收。

先做能通过上述反例的完整闭环，再决定哪些视图需要持久化、哪些阶段需要额外模型。自然性与可展开性仍以实际候选的独立判断和用户反馈为准；双方愿意的现实亲近不能从内部评审推断。
