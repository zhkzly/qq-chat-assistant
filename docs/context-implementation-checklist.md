# Acceptance checklist

- [x] A scoped private conversation persists across reloads and never becomes actual QQ history.
- [x] Empty QQ history still permits private help; the goal survives local method changes.
- [x] User notes have discussion/draft/disabled uses, and user goal/material edits remain authoritative.
- [x] Current evidence, later corrections and coverage are represented without silently truncating critical messages.
- [x] Discussion, options, clarification, review and optional drafting work without requiring three alternatives.
- [x] Draft model payload excludes private goal/history and discussion-only materials, including mixed-request tests.
- [x] State patches require valid source references and matching versions; failures and partial help do not claim full processing.
- [x] Contact/model/permission/source changes invalidate pending responses and derived context; correction/deletion affects future requests.
- [x] Feedback, selected/copied drafts, actual sends and replies remain distinct; no automatic skill promotion.
- [x] Existing functional checks plus the new synthetic end-to-end/UI scenarios pass; actual QQ/model efficacy remains explicitly untested.
