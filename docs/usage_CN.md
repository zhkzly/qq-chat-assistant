# 使用说明

> 完整组织与信息生命周期见[重构说明](relationship-assistant-refactor-note_CN.md)。“想和她聊”和“换个切口”都只生成当前候选，保留输入框未发送的想法；「聊一聊」或 Ctrl+Enter 才提交这段想法。

## 窗口里的三个入口

默认打开「和助手商量」。当前好友始终显示在顶部，「现在可以这样聊」放在私下讨论之前。设置中开启「新消息自动更新建议」后，有待回应的新来信会自动产生候选；解释默认折叠，首条可直接复制或采用，实际发出后该轮候选撤下。即使没有新来信或新近况，也可以点「想和她聊」找具体切口。有完整当前候选时，「换个切口」会要求换一个有实质区别的内容方向，并参考刚才这一条，不能只换几个词；没有当前候选时显示「找个切口」，提供常规手动帮助。这两个动作不提交私下输入框的文字。

底部固定输入框用于近况、困惑或额外要求，不必先填写目标或选择方法。“帮助方式”可选择下一次讨论、组织表达或回顾；点击菜单不会立即提交。点击「聊一聊」或按 Ctrl+Enter 才提交。也可直接说「不要这么直白，换一句」，新稿会替换主候选，旧稿不再占位。自动生成时可直接提交自己的要求；单纯解释保留在讨论里，不自动复活旧稿。

- **QQ 记录**：查看双方实际消息、指定回复重点、预览图片及读取更早记录。主界面的一行 QQ 摘要可以直接打开这里。
- **关系与记忆**：查看“关于我／关于她／我们的互动”的有来源理解，可纠正或停止采用；查找旧事，查看实际互动回顾与个人帮助经验，按需编辑目标或背景。
- **回复草稿**：采用参考表达时自动打开，也可从右上角打开。编辑、复制或填入 QQ 后，由你检查并发送。返回讨论会保留草稿。

「设置」集中放置模型、API 与回复偏好。切换这三个工作区会保留当前私下输入和阅读位置；更换好友时按账号与好友隔离内容。助手正在思考或整理旧讨论时，也可选择下一次帮助方式、继续编辑；它不会更改或取消当前请求，不会自动开始下一次请求。新编辑或模式选择后，旧回复不会清掉待提交输入。

## 持续私下助手

在助手主区域直接说目标、近况、困惑或明确的保存/更正要求。目标和素材可从自然讨论保存，表单是可选编辑入口；需要参考表达时可以说“就按刚才那个”或点选一个方向。快速回复和自动建议也共用长期背景。背景区可搜索以前说过的事、查看整理状态、确认或撤销具体修改。所有内容按当前账号和好友隔离，仍由你在 QQ 手动发送。完整说明见 [上下文管理](context-management_CN.md)。

## 打开与选择好友

在应用菜单打开「QQ 聊天助手」，或在 `~/pycodes/qq-chat-assistant` 运行 `npm start`。首次启动会在本地 QQ 运行时和助手服务就绪后直接打开助手窗口；需要登录时，仍按 QQ 原来的流程登录。在好友私聊输入工具栏点击「✦ AI 建议」，或按 `Ctrl+Shift+A`，也可重新打开助手。再次打开会复用助手窗口。

如果已经运行的是普通 QQ，助手无法直接附加到这个进程。请先保存未发送的文字，从 QQ 菜单退出，再打开「QQ 聊天助手」。启动器不会替你关闭 QQ；服务连接失败会显示提示，不再只有看不见的终端报错。原来的 QQ 安装无需修改或重新安装。

点击顶部当前好友，填写好友 QQ 号后点「连接会话」即可切换。部分好友的身份或历史还没有进入本机缓存，需要先在 QQ 打开该私聊再连接；助手不能承诺读取腾讯服务器的全部历史。错误、空记录和本机已有缓存分别显示，不再一直假加载。

## 浏览、图片与表情

「QQ 记录」显示最新 100 条，向历史面板顶部滚动或点击「查看更早消息」会继续展示已经缓存的记录，每次 100 条。「从 QQ 读取更早记录」才会请求新的历史页；两者用途不同。后台首轮最多读取 20 页，进一步读取最多 200 页。可读取的数量随本机缓存及继续交流变化，以界面覆盖范围为准。

图片的「查看图片」只读取本机 QQ 已缓存文件。尚未缓存时先在 QQ 查看原图后重试。本次已经实测一张该好友的本机缩略图可显示，但不保证所有旧图片仍可用。图片预览与模型看图是两个独立操作。

已知 QQ 表情用相近 Unicode emoji 显示，和原版 QQ 图案可能不同。未知表情显示名称或编号。新生成的建议不再保留 `[表情]` 占位；模型需要表情时使用可复制的 Unicode emoji。已生成的旧建议需重新生成才会更新。

## 建议、复制与填入 QQ

直接在主界面讨论，或点击「想和她聊」。助手会依据当前情况商量下一步或提供参考表达，数量不固定。参考表达的「采用到草稿」会打开独立编辑窗口，可以修改，再点击「复制回复」或「填入 QQ 输入框」。长期回复偏好可在设置中修改。草稿按账号和好友保存在本机，未发送草稿不算聊天消息。

回填前直接核对当前 QQ 联系人及输入框，写入前再核对一次；同一好友开了多个窗口时优先使用点击「✦ AI 建议」的那个窗口。不能确认时会取消。QQ 输入框已有文字时先询问是否替换。回填不会触发 QQ 发送；发送按钮和回车由你操作。

连续收到多条消息时，默认把最近最多 8 条连续来信作为回应重点，结合其余上下文按话题合并回复。可以勾选某一条或多条「重点回复」（最多 8 条），旧消息也会优先进入本次模型上下文；点击「回到最新消息」取消手动重点。选中重点后新来信不会擅自改变所选目标。

这里选择的是 AI 回应重点，不会生成 QQ 原生引用框。需要针对某条消息引用回复时，在 QQ 对原消息选择「回复」，再复制建议到该输入框；发送仍由你操作。

收到或确认已发送的新记录会更新上下文。「新消息自动更新建议」只更新参考文本。关闭助手窗口会暂停自动模型生成。

## 模型设置与看图

点击右上角「设置」后可以看到 API 配置与模型下拉框；「刷新列表」从所选服务读取 `/models`。图片生成专用 ID 会标注并禁选；列表不代表每个 ID 都有调用权限或支持看图。

展开设置里的「管理 API 配置」可新增多套具名配置，各自保存地址、密钥、模型和图片能力。原配置原地址下，密钥留空才会保留；更换地址必须重新填密钥，免密本地服务则明确勾选「无需 API Key」。不提供模型列表的服务可手动填写模型 ID。目前支持 OpenAI 兼容 Chat Completions 接口，原生 Claude/Gemini 接口需要经过兼容代理。

模型和目的地以设置中当前选择及授权为准。早期发布曾使用 `gpt-6.1-sol` 与本机 `http://127.0.0.1:8317/v1` 代理；后续验证还使用过 Astra 和 Claude，这不代表每次更新会替你切换模型。模型本体不是由本项目部署，本机代理连接其配置的上游服务。已核验的部分 Claude 4.6 ID 使用结果函数封装兼容代理；该封装只接收数据，不会执行 QQ 操作。

文字授权限定当前 QQ 账号、好友、模型、API 地址。页面显示目的地，点击「允许当前会话使用这个模型」后才能生成。此前自动审批拒绝过缺少目的地授权的真实聊天测试，因此保留这道授权门；当前用户已通过页面授权的会话可以正常使用，不代表其他会话已获授权。

模型看图还需：在设置确认所选模型支持图片；在记录里勾选「本次让 AI 看此图」（最多 3 张）；勾选并提交图片授权。只把所选图片和本次文字上下文提供给模型。已经用虚构蓝色方块验证当前模型视觉请求返回成功，没有用私人 QQ 图片做模型测试。

主界面的「本次参考」显示最近一次请求使用的目标、当前问题、来源及讨论整理信息，完整请求放在折叠的技术详情中；查看不会执行模型请求。实际选取规则见 [上下文管理](context-management_CN.md)。

## 导出与停止

在「QQ 记录」展开「导出记录」，用「导出 JSON」或「导出文本」保存当前账号/好友的本机可访问记录，带消息 ID、双方方向、时间和覆盖范围，不含草稿或私有媒体路径。文件可能包含私人聊天，项目不会上传它们。

暂停建议：取消自动更新或关闭助手窗口。退出助手版 QQ：从 QQ 菜单退出；之后照常启动原 QQ。原安装 `/opt/QQ/qq` 未修改；项目 `data/` 保存本机记录、配置和运行时，已排除 Git。诊断 `npm run diagnose` 不输出聊天文本或模型密钥。


## 从实际相处中调整帮助

可以先说“我想更靠近她，但不知道今天该不该找她”，也可以直接说“我想表达好感，帮我组织一下”。助手会按意图选择帮助方式，历史少不会强制先填资料。你最近发生的事既能作为话题，也能只用于私下商量。

对某一条建议或候选表达点反馈，助手保留被评价的准确原文；“这次太长”只作为这次的反馈。回顾时可能出现“个人帮助经验”候选，查看适用情况后可以启用、修改或停用。它调整助手怎样帮助你，不代表已经验证怎样让她喜欢你。

复制、编辑和填入草稿分别记录；真正发出的消息仍从 QQ 读取。文字相似时只提出“可能用了这条表达”，由你确认或否认。你完全自己写的消息、一起打游戏等事，也可以单独回顾，不要求先用 AI 草稿。

记忆维护状态显示剩余待整理资料。少量新增信息通常等批量或空闲后整理，新信息仍可立即用于当前讨论。来源更正、遗忘及停用立即阻止旧推断继续采用，无需等下一次模型调用。更完整的例子和边界见 [关系助手完整流程](relationship-learning_CN.md)。


## 保持这一轮商量的方向

直接说这次想了解、回应或表达什么；还没想清楚也可以先商量。已有当前方向时，讨论区会简短显示，展开可看目的、局部限制与未知。“调整”把可编辑说明补入输入框；你可继续修改后提交，不会自动交流。改主意、换话题或结束这轮都能用自然语言说，局部含蓄不限制今后明确表意。

反馈可选择“记下反馈”，或“反馈并继续商量”。后者会联系你评价的准确建议给帮助，具体想要句子时直接写在反馈中。失败会保留反馈和对象，明确重试继续使用同一份反馈。原本尚未提交的其他想法保持独立。流程与边界见 [当前话题说明](conversation-direction_CN.md)。

## 私下讨论变长以后

长篇讨论需要整理时，助手会自动处理较早的原始轮次，并显示“正在整理较早的讨论”。有仍有效的缓存时直接复用。你不必清空聊天或重新概述全部背景；“刚才第二个”“这次别追问”等仍应结合当前原话、实际候选和局部限制处理。整理后的摘要只是导航，旧原文仍保存在本机，必要时可以按来源取回。

这一步使用当前已经授权的同一主模型，不新增摘要服务。默认正文48,000字节、完整文字请求64,000 UTF-8字节，不是48k/64k tokens。一次帮助默认最多4次HTTP，包含整理、普通回答、成稿及修复/重试；首次整理后出稿通常3次，缓存后出稿通常2次，缓存后回顾通常1次。数字是常见路径，不保证任何补查组合都能完成。

如果原话、明确选中的内容本身太大，或整理返回格式/来源无法校验，系统仍可能停止并保留输入；不会擅自截掉限制或删除旧讨论。可查看具体错误和“本次参考”，按需要缩小所选范围或明确重试。来源更正、忘记、目标/方向或模型目的地改变后，旧缓存必须重新校验，不能因曾整理过就继续采用。

整理能改善接续与容量，不能保证每句都自然。尤其调侃仍需你检查分寸：测试曾出现把温和游戏反差改成“洗心革面、从打人改成动脑子”的较重措辞。具体行为与验证边界见 [长讨论自动整理](discussion-compaction_CN.md)。

Claude兼容仍有明确边界：同形合成回放曾在修复后继续返回坏JSON而停止，没有草稿交付。若遇到相同格式错误、当前服务列表也实际提供 `gpt-6-astra`，可在设置手动选择并核对授权后比较同一请求；已知案例中Astra成功，不代表它普遍更适合关系沟通，系统不会为此自动改模型。详细失败记录见 [整理能力与验证边界](discussion-compaction_CN.md)。

## 建议先给出，部分背景待整理

后续恢复改动在私下讨论、回顾或“结合 QQ 给建议”的结构化回答出错时，使用原有一次修复机会重新生成可读建议。界面显示“已先给出建议；部分背景整理未完成。”，表示可以继续商量，不能据此认为目标、当前方向或长期记忆已更新。此前已经成功执行的明确操作仍保留真实回执。已有话题可能暂时提示“这次想法待核对，以最新原话为准”。

私下恢复文字没有“采用到草稿”按钮。需要发给她的表达时，继续说“按这个意思给一句”，系统仍先检查这次可表达的素材和限制。准备失败不会跳过这一步；准备已通过、最后成稿格式失败时，可恢复一条完整参考表达，标为“表达参考 · 请核对”，再由你编辑、复制或填入未发送的 QQ 输入框。输入与下一次帮助方式继续保留，没有自动发送。

恢复沿用当前已授权模型、地址和每次帮助默认4次 HTTP 上限，不需要另填提示词或自己修 JSON。本次排查使用的 `claude-sonnet-4-6` 和本机8317代理未被更换。模型再次返回无效内容、网络或来源变化、严格准备无法校验时，仍可能停止并显示原因。尤其要核对参考话语有没有虚构经历、换掉选定意思或变相追问；首轮回放确实出现过这些问题。第二轮的受限成稿与后续回顾符合该例最新意思，私下建议却仍有预设场景、调侃聪明程度的问题，不能整轮都算自然度通过。候选功能与浏览器检查通过，原生集成待确认；最新实现和验收状态见 [回答恢复说明](response-recovery_CN.md) 与 [恢复证据](response-recovery-evidence.json)。
