## Complete product path

`activity-evidence.cjs` owns original-span selection, minted identity, body-free
gap state and public projection. It reuses canonical event/claim rows and the
existing `memory_gaps` table. No new database or activity registry is introduced.

The program mints an activity ID once from validated explicit NEW creation and
persists it. The model selects existing offered activity refs independently of
display `activityKey`. Original source/RV/range anchors define the entity; label
changes do not remint it. Repeated identical NEW definitions within one proposal
declare one creation. An already-bound original range requires the offered ref;
there is no semantic ID inference, label-similarity matching or unique-target fill.
An existing ref can be explicitly rebound to fresh original proof after a source
revision. Without surviving proof its label is unavailable and uncertainty stays.

Every current model event proposal, including a legacy result envelope, requires
activity selection, an exact original world-statement witness and a time basis.
Actual QQ speech acts can use their statement clock. Reported occurrence needs
an explicit original time witness, or remains unknown. Private question/report
time is never an automatic event occurrence. `plannedFor`, occurrence and report
time remain separate. Unknown dates do not erase a supported past occurrence.
Passing a planned date does not create completion. Generated drafts, copied text
and private wishes are not evidence of actual sends or shared events.

Withdrawal writes program knowledge state, not a new world event. Native gaps
retain activity identity, original reference metadata, the affected world-order
barrier and separate knowledge-change time; they retain no withdrawn text or
generated label. Native recallTime is preserved when valid. The world barrier is
not the recall date: an October 4 reconfirmation newly reported October 7 can
follow an October 3 cancellation even though evidence was withdrawn October 6.
An old October 1 acceptance, reread or late report of that old acceptance cannot.
Unknown or overlapping world order remains qualified. Legacy hash-only gaps stay
opaque unresolved state; no digest is reverse-matched to a new label. Old-only
NEW identities remain provisional. Genuine fresh current reports can be usable
with that unresolved scope explicitly qualified.

An explicit current agreement without a known historical occurrence clock uses
the existing coordination-claim channel with optional activity/current-state
association. The program binds source/as-of/user-report authority to that claim;
it creates no fake event date. Public activity, experience, foreground input and
UI distinguish currentReportedState from the retained historical evidence gap.
A later contrary report with unknown occurrence qualifies an older current-state
claim; a known older world event reported late does not become newer merely by
arrival time. Pure questions can finish processing with no-change. Correct domain
uncertainty is completed processing, not a permanent semantic-pending retry loop.

Native event evidence errors are collected across independently fixable fields
and records through the existing bounded validationIssues machinery and single
correction. Feedback includes field paths and actual offered choices, preserving
the complete original input. There is no extra correction or model phase.

## Consumers, privacy and compatibility

Canonical Store API compatibility remains explicit and qualified as legacy/unbound;
it is not a current model-writer escape. The shared relationship protocol generator
keeps default canonical instructions byte-equal to 038, while memory requests and
their correction select the native activity contract. Both native schema and
result-tool container normalization declare the same fields. Memory wire version
is `evidence-backed-understanding-2026-11-01.2`; activity protocol is
`activity-original-evidence-v1`. Unrelated processor/bootstrap and SQL versions
remain unchanged; no retraining or destructive migration is forced.

Read DTOs and activity experience observations carry complete original identity,
statement, time and plan dependency closure. Late budget eviction re-grounds all
activity views: unavailable labels/current reports are removed or downgraded,
while opaque gap state remains. Qualified stored activity summaries may remain
navigation, but every original RV is bound into publication/artifact dependencies;
those refs are not falsely marked as delivered/reviewed bodies. Postpublication
forgetting an identity original redacts the dependent artifact. Scope, original
string IDs, source body/RV, CAS, withdrawal and atomic-progress guards remain active.

Forward upgrade from a frozen 038-created fictional gap database preserves raw
IDs/times, notes and permissions, feedback, recalled-source state and the original
hash-only gap row. That old gap is projected as unresolved instead of being assigned
a guessed identity. This is a forward compatibility check, not production or
down-migration evidence.

## Remaining limits

The model still judges whether an original reports a world event/current state,
which identity it concerns, and what an explicit time means. Exact span membership
and program IDs do not prove entailment, actor correctness or truth. A false model
interpretation can still produce a false record; independent actual-output review
is required. There is no keyword classifier or blanket semantic critic.

Unknown affected-world order is conservative; current-state assertions are a
separate knowledge axis. Legacy identity loss cannot be recovered from a hash.
The memory activity menu is bounded with explicit omission counts; omitted targets
can require a different source selection or refusal rather than a guessed write.
Public gap inventories and foreground opaque-gap metadata still scale with the
stored scope; extremely large legacy gap inventories have not been stress-tested.
No rendered desktop lifecycle or existing production database was exercised.

Artifacts and complete changed files are under `.goal-runs/engineering-039/`.
`ui-seed.cjs` supplies real Store/native-decoder gap and current-report fixtures for
the coordinator's UI verification without handwritten ideal UI DTOs or model calls.
