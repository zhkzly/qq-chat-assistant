# 评测保真与覆盖第二版验收

本轮修复评测本身，不修改生产`src/`、QQ安装、真实聊天数据库或模型配置。原始基础JSONL和原来3个历史事件场景保持不变；评测数据、标准和通用运行器仍独立于产品架构，产品知识只留在可替换适配器中。

## 修复与补集

- 回答投影保留实际可读的解释、正文、带标签的建议、表达选项、恢复提示以及可展开的方法／依据文案。界面布局、按钮及静态来源目录不属于此次内容投影验收，没有桌面GUI验收。
- 历史便签保留原ID、日期、用途、类型和来源引用；新建便签仍使用当前时间，避免把历史内容伪装成新输入。
- 记忆准备按实际提交回执、版本和分段游标判断进展。16,000个中文字符的单条来源通过多段完成；真实卡住或无有效提交仍会被拒绝。
- 反馈可选择本轮实际返回的主回答、自动建议或中间回答，传递真实`reply_id`；目标不存在时不执行，不预先断言回答必然犯错。切点后的助手回答只能来自运行系统，不能由案例作者插入。
- 支持可观察的目标变化、私下来源／笔记删除或停用、已经发生的QQ撤回与缺失图片。被撤回的证据及依赖它的笔记不能继续支持新的证据引用。
- 原空闲确认案例的评审要求已做版本化修正：允许不虚构、不承诺赴约的待确认草稿，也允许私下澄清。原始输入没有改变，旧标准哈希和修正理由保留。

总计**38场景、81步骤**，包含欢迎的主动性、低回应、情绪袒露、误会修复、明确拒绝、模糊表述对照、真实回答反馈、永久目标改变、不同来源撤回、缺失图片和长私下讨论。覆盖矩阵及未覆盖范围见[覆盖说明](../evals/assistant/COVERAGE_CN.md)。这不等于覆盖所有聊天情况。

42条原始私下记录超过57KB，实际合成回放触发了记忆准备和讨论压缩；单条长来源有15,617字符，其中14,289个汉字，没有预填正确记忆。回放数据哈希为`d7890b62c8c92e7e496d631ca8f2c255bd6871380d779e194fbb85125a0e7aa0`，策略为`observed-history-replay-v2`。

## 全量接入检查与保留的失败

最终合成传输回放尝试全部38场景：79步骤完成链路检查，1步骤执行错误，1步骤未执行。模型响应是合成占位文本，不能用来评价自然度；`executed_review_required`只是运行器状态名，不代表已有可判质量的真实模型建议。总状态明确为`incomplete`，没有填写质量通过。产物在`/tmp/qq-eval-fidelity-offline-20261030-final/`。

失败的是`coverage-long-single-source`：4次记忆处理后，准备阶段待处理数已经为0；回答阶段仍被产品上下文预算拦截。因此此前适配器把正常分段误判为无进展的问题已解决，但现有助手对该长输入仍未完成回答。案例保留，不缩短来换取绿灯。显式`--continue-on-case-error`让其他独立场景继续执行，失败与未执行步骤仍在记录中。

另外做了一次**私下商量专用的两轮定位探针**，明确不要求出稿，4次HTTP调用，第二轮确实绑定第一轮真实返回的ID并完成调用。产物在`/tmp/qq-eval-private-feedback-probe-20261030/`。它证明实际引用通路接通，不替代出稿失败案例，也没有按原出稿标准判通过。

## 评审校准与分歧

当前参照20条，版本`assistant-calibration-reference-v2`，数据哈希`2da7d8816ba597e3005e22381a085431664d9617178f68651a6c633c29143640`。全部为AI编写、协调者复核、未经用户本人确认的可见开发参照；原16条及评分规则未改变，v1以原哈希完整归档。

原16条由两个隔离上下文的AI评审盲评，均与参照的总体等级一致14/16。两者都识别5条坏回答，未将6条可用回答判为重写；对c08、c12的“小改／重写”及硬失败尺度有分歧，均保留，没有回改参照来提高分数。

新增4条补齐私下内容泄露、复制不等于发送这两个硬失败类别。它们由一位独立评审追加判断；第二位没有追加评分。合并评审A时，逐项验证旧16条盲评输入和规则未改变，并明确保留复用来源，没有伪称20条都是新评分。合并结果：总体一致18/20，参照中的坏回答识别7/7，可用回答被判重写0/8；硬失败集合完全一致17/20。另明确报告13条非硬失败参照中有2条被标为硬失败，避免仅报“可用回答误杀0”掩盖尺度差异。c17还存在私密泄露与边界违背的合理重叠标记。

原始评分、哈希绑定、分歧及比较结果保存在[校准结果目录](../evals/assistant/calibration/results/20261030/)。小样本和AI参照不能证明评审已获得稳定的人工偏好一致性，更不能证明助手质量。校准工具不会自动调用评审或填写未运行评分。

## 验证边界

工程检查、真实调用、语义评审和现实关系效果分别记录。105个测试文件、720项工程检查通过，语法与差异检查通过；针对空反馈和历史版本误标的加严检查另行通过。精确记录见[机器记录](eval-fidelity-v2-verification.json)。没有启动自动Goal、没有操作真人QQ或自动发送消息，没有优化生产助手以掩盖失败。

下一轮产品优化已有具体失败证据：规划引用与原文不对应、局部反馈被分类为稳定偏好、长输入仍超预算，以及情绪回应说得过满。可先处理这些偏差，再用同一批冻结输入与标准复验。可访问图片的真实理解、语音、多账号并发、长期自然交流分布和用户本人声线确认仍未覆盖。

真实执行的可读请求／响应与情绪评审包另保存在[虚构执行证据](../evals/assistant/evidence/fidelity-v2/README.md)，没有真实聊天、认证头或API密钥。共享副本剔除提供方内部推理字段并保留原始响应哈希；原始本地文件未被覆盖。
