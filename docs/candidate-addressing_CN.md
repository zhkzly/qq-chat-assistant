# 候选字段地址契约

020 候选修复第 040 轮暴露的机械地址不一致：同一条有依据的事实拒绝，使用 `candidate.suggestions[0].text` 时未能对应内部的 `suggestions[0].text`，因而没有进入原有修复流程。旧输出和失败证据保持不变。

这个修复服务于原有长期目的：帮助用户根据真实处境理解、接话、分享自己并延续双方愿意的交流；当前应用是逐渐了解和亲近，也支持其他目的。它不改变 v2 核对的语义标准，也不把“拒绝更多答复”当作目标。

## 同一套程序地址

[`candidate-field-paths.cjs`](../src/candidate-field-paths.cjs)只枚举当前可见候选中的正文、私下解释、建议文字及样式、选项标签。它同时供[私有核对帧](../src/whole-answer-fidelity.cjs)和[结果 schema](../src/model-response-format.cjs)使用，避免各自猜测字段根。

核对输入中的 `candidatePaths` 是程序生成、不可修改并纳入帧哈希的地址清单。工具载体的 `path`、`relatedPath` 和顾虑的 `path` 使用本次清单作为枚举；每次请求独立构造 schema。JSON 与纯文本载体也会收到同一清单。清单只定位字段，不提供事实、来源或分享许可。

| 地址 | 处理 |
|---|---|
| `suggestions[0].text` | 本次清单中存在时直接使用 |
| `candidate.suggestions[0].text` | 仅移除一次 `candidate.`，且余下地址必须在本次清单中 |
| `candidate.candidate.suggestions[0].text` | 拒绝重复前缀 |
| `evidence[0].text`、其他根或隐藏字段 | 拒绝，它们不是候选可见字段 |
| 其他请求才有的建议索引 | 拒绝，不根据文字相似度匹配 |

规范化发生在引用逐字核对和相互冲突陈述的比较之前，因此加一个前缀不能把同一字段、同一引文伪装成不同陈述。未知地址仍产生 `fidelity_candidate_path_invalid`，指出具体字段、收到的地址和本次可选项；不会被静默忽略或改判为允许。

等价转换记录在私有 `manifest.fidelity.addressNormalizations`，原始模型响应保持原样。候选正文、原文引用、来源版本、账号与联系人、图片、帧哈希和撤回检查均沿用原机制。

## 调用与证据范围

正常路径仍是完整主答复、程序来源准入和同一选定模型的只读核对。有依据的拒绝可以进入原有唯一一次完整重生成，再次准入和核对；地址规范化本身不增加模型调用或修复名额。不确定、无效或过期结果仍不能发布。产品任务预算及 48,000 字节上下文、64,000 字节序列化请求上限保持不变；用户仍自行修改、复制并在 QQ 发送。

提示版本更新为 `goal-context-2026-10-31.9`，核对语义契约仍为 `whole-answer-fidelity-v2`。独立地址测试验证了两条四调用合成路径：拒绝后生成有依据的候选，或提出适当的私下素材问题。功能通过只证明该地址契约和生命周期可执行；真实模型的输出质量、素材真实性、个人口吻及关系结果仍需相应证据，不能由此推定改善。
