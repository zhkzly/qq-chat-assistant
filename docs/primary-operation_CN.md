# 主助手的单一操作契约

本次调整面向有效帮助的交付。实际第 028 轮已提供所需上下文，模型仍同时返回私下商量标记与消息计划，程序因字段冲突拒绝了整轮结果，尚未进入成稿。标记一致性不能代替用户是否真的得到帮助。

模型使用现有单一结果工具，选择一项操作；内部展示类型和交付状态由程序构造，不再要求模型另外给出一个需要与内容保持一致的受众式模式。

| 操作 | 含义 | 仍须遵守的边界 |
|---|---|---|
| advise | 商量、解释或比较方向 | 保持私下帮助，不偷偷进入消息准备 |
| prepare_message | 使用准入素材准备可用消息，可附私下说明 | 原始来源、分享限制、当前要求及真实选择继续有效 |
| lookup | 补读所缺资料，声明续接目标 | 有界读取，保留同一请求已有的消息交付要求 |
| clarify | 核对影响帮助的关键缺失 | 一个规范问题及可选原因，不编造事实或已执行效果 |

操作不是用户意图的形式化证明。自然语言要求仍可能被误解，明确要求完整消息却只收到建议时，实际评测仍应判失败。操作也不是新的事实、分享许可、实际发送或关系进度。

程序单独维护请求内的产物要求：进入消息准备或服务消息产物的补读后，补读、修复及同任务恢复不能通过改成建议而宣告交付完成。合法澄清表示被关键缺失阻塞，不等于消息已交付。新的私下“为什么”回合需要按当前要求处理，不能机械继承旧任务的交付义务。

有效 JSON 中已识别的操作可以建立请求内工作承诺，即使后面的素材结构需要修复；这不允许无效内容产生任何数据、动作或进度提交。损坏 JSON 或未知操作不应靠猜测建立承诺。混合的核心操作载荷仍须原子拒绝，不能自动升级成出稿。

独立存储或遗忘动作沿用既有验证与回执机制。若动作改变上下文，先重建后继续读取或回答，避免沿用已经失效的计划。只报告确实执行的效果，不因后续消息失败就丢掉真实回执，也不把尚未执行的提议写成已完成。

现有原始人类控制、界面选择、派生指导和准入素材各自承担原来的用途。复用同一提供方、命名结果载体、字节预算、一次修复和过期结果围栏；不增加核验模型或自动发送能力。

候选尚未完成实际验收。首组保留局部纠正三步及明确完整消息/实际输出反馈两步，冻结原始输入和外部标准，再对真正输出独立盲评。功能检查、前版的通过评分或操作选择正确，都不能单独说明整个 Goal 已完成。
